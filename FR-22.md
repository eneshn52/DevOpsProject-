# FR-22 local review

After FR-21 generates a source string and tests it, the worker sends the task description,
requirements, source and full execution report (including case inputs, expectations, streams,
and errors) in a separate Ollama request with a reviewer system prompt. The review call uses
the worker's existing Ollama URL and credentials. The reviewer can use the generation model
or a separately selected local model. The worker continues heartbeats during review. No
separate reviewer daemon is required.

The worker posts one report to the existing test-result URL. FR-21 fields keep their meanings;
`status` at the top level describes tests, and `review.status` describes review. The master
stores both in Task.test_result. It marks the task COMPLETED only for passing tests and
an approved review. Failed tests, rejection and review errors produce FAILED. Old reports
remain readable, and newly submitted legacy reports without a verdict cannot complete a task.
No database migration is needed beyond FR-21. This applies to the existing Python solve(value)
workflow. The reviewer is an LLM and can miss issues. Its comments do not execute as commands.

## Run on one computer

Run each terminal from the repository root. If the FR-21 local master was running with
`--noreload`, stop it with Ctrl+C and restart it to load the new endpoint logic.

1. In PowerShell, start Ollama if it is not already serving:

   ```powershell
   $env:OLLAMA_HOST = '127.0.0.1:11434'
   ollama serve
   ```

2. In a second terminal, prepare and start the local master:

   ```powershell
   py -3.14 -m venv .venv
   .\.venv\Scripts\python -m pip install -r requirements-dev.txt
   .\.venv\Scripts\python manage.py migrate --settings=django_settings.fr21_local
   .\.venv\Scripts\python manage.py runserver 127.0.0.1:8000 --settings=django_settings.fr21_local --noreload
   ```

   Skip venv creation and dependency installation if using the existing FR-21 environment.

3. In a third terminal, list installed models, select the generator and reviewer
   (the same installed tag works for both), and submit the doubling task. To install
   a missing model first, run `ollama pull` followed by its tag.

   ```powershell
   ollama list
   $coder = Read-Host 'Installed coding model tag'
   $reviewer = Read-Host 'Installed review model tag'
   $path = .\.venv\Scripts\python manage.py fr21_demo --settings=django_settings.fr21_local
   .\.venv\Scripts\python worker/worker.py --agent-name fr21-local --model $coder --review-model $reviewer --run-tests --once
   $report = (Invoke-RestMethod "http://127.0.0.1:8000$path").data
   $report | Select-Object status,exitCode,attempt
   $report.review | ConvertTo-Json -Depth 8
   ```

   The worker runs the oldest eligible assignment. If the log shows an older task ID,
   repeat the worker command until it processes the ID in $path, then read the report.
   An approval run should show passed tests, an approved review and comments about the source.

4. Submit a deliberately contradictory fixture; the second case expects 5 from doubling 2:

   ```powershell
   $cases = Join-Path $env:TEMP 'fr22-rejection.json'
   '[{"input":2,"expected":4},{"input":2,"expected":5}]' | Set-Content -Encoding ascii -LiteralPath $cases
   $path = .\.venv\Scripts\python manage.py fr21_demo --settings=django_settings.fr21_local --cases $cases
   .\.venv\Scripts\python worker/worker.py --agent-name fr21-local --model $coder --review-model $reviewer --run-tests --once
   (Invoke-RestMethod "http://127.0.0.1:8000$path").data | ConvertTo-Json -Depth 8
   ```

   Inspect cases, review.comments and review.rejectionReasons. An error verdict means the review
   could not finish, for example due to malformed JSON, an unavailable model or a timeout.
   A delivery failure is reported by the worker; GET the task URL to check what reached the master.

## Review object examples (illustrative)

```json
{"status":"approved","comments":["value * 2 doubles both positive and negative integer inputs."],"issues":[],"improvements":[],"rejectionReasons":[],"model":"<selected reviewer>"}
```

```json
{"status":"rejected","comments":["Both cases call solve(2), which returns 4; the second expects 5."],"issues":["The second expectation contradicts the task."],"improvements":["Correct the second expectation."],"rejectionReasons":["Case 2 failed."],"model":"<selected reviewer>"}
```

A review error uses the same fields with status "error" and the diagnostic in comments and
rejectionReasons. Generation without source records a review error. The system does not
retry rejected tasks or assign them to another agent.

## Automated validation

```powershell
$env:USE_SQLITE = 'True'
$env:FR21_MODEL = $coder
$env:FR21_OLLAMA_URL = 'http://127.0.0.1:11434'
.\.venv\Scripts\python -m pytest -q -rs
```

The live-model tests use the selected model for both roles and start a separate local
Django test server and database. Without FR21_MODEL, the model-dependent cases skip.
