# FR-21 local acceptance run

Run these PowerShell commands from the repository root. This uses the existing Django master, scheduler, heartbeat and HTTP worker. The demo settings store data in `fr21-local.sqlite3`. The demo command registers one specialist with example capability scores so the existing scheduler can assign it work.

## 1. Install and start the master

Use Python 3.14 (the version used for validation) and a local Ollama installation with a downloaded model.

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements-dev.txt -r benchmarks/model_test/requirements.txt
.\.venv\Scripts\python manage.py migrate --settings=django_settings.fr21_local
.\.venv\Scripts\python manage.py runserver 127.0.0.1:8000 --settings=django_settings.fr21_local --noreload
```

## 2. Start Ollama

If Ollama is already serving on its default local port, use that instance. Otherwise run in another terminal:

```powershell
$env:OLLAMA_HOST = '127.0.0.1:11434'
ollama serve
```

## 3. Submit work and run the worker

In another terminal at the repository root:

```powershell
$models = (Invoke-RestMethod http://127.0.0.1:11434/api/tags).models
$models.name
$model = Read-Host 'Enter an installed coding model name from the list'
$resultPath = .\.venv\Scripts\python manage.py fr21_demo --settings=django_settings.fr21_local
.\.venv\Scripts\python worker/worker.py --agent-name fr21-local --model $model --run-tests --once
(Invoke-RestMethod "http://127.0.0.1:8000$resultPath").data | ConvertTo-Json -Depth 8
```

The worker claims the oldest eligible task. Omit `--once` to keep polling. A successful report has `status: passed`, `exitCode: 0` and two passing case records in fixture order. The task becomes COMPLETED. A wrong answer records FAILED and includes the observed return value in the failing case detail. The report includes the source and attempt number. Duration is measured in seconds. Monty executes function calls via an interpreter API, so exitCode is the **suite's logical exit code**. Each case has separate stdout, stderr and error detail.

For the missing-file check, submit again with `--cases worker/absent-cases.json`, keep the new result path and repeat the worker and inspection commands. Expect `missing_tests`, exit code 1 and zero case records after generation.

## 4. Repeat automated validation

```powershell
$env:USE_SQLITE = 'True'
$env:FR21_MODEL = $model
$env:FR21_OLLAMA_URL = 'http://127.0.0.1:11434'
.\.venv\Scripts\python -m pytest -q -rs
.\.venv\Scripts\python -m unittest discover -s benchmarks/model_test -p 'test_*.py'
```

The live tests start a disposable Django server and test database. One test substitutes deterministic generated source, another calls Ollama when FR21_MODEL is set. PostgreSQL row-lock tests require PostgreSQL. Ctrl+C stops foreground services.

## Runtime contract

Set Task.test_cases to an array of up to 16 JSON input/expected pairs to opt a task into Python function execution. An empty array records missing tests. A null field denotes an ordinary task. The worker uses the existing next-task endpoint with `?runner=python` and submits the report to `/api/agents/{agent_id}/tasks/{task_id}/test-result/`. The same URL accepts GET. Submission requires the active assignment and attempt. Existing workers can continue to use heartbeat mode. Install `worker/requirements-tests.txt` on workers using `--run-tests`.

The code contract is a pure Python `solve(value)` returning a JSON value, using the Python subset supported by Monty. Tests are supplied by the task author. Each input runs in a fresh sandbox with no host callbacks or mounted directories, an 8 MB interpreter heap, a one-second execution budget per feed, bounded output and a four-second host request timeout. Code that requires third-party libraries, project files, shell commands or other languages needs a different runner. This workflow does not discover or execute arbitrary repository test suites.
